## 3. Golden Master 전략 개요

### 3.1 이중 Golden Master (설계)

| 레이어 | Phase | 기준 파일 (예정) | 본 세션 |
|--------|-------|------------------|---------|
| **Domain Service** | Phase 1 | `tests/golden/domain_golden_expected.txt` | ✅ **완료** |
| **HTTP 웹앱** | Phase 2 | `tests/golden/http_golden_expected/` (예정) | ⏳ 미착수 |

Domain Golden은 TextAnalyzer·Filters·CsvParser의 **결정적 출력**을 고정한다. HTTP Golden은 POST `/analyze`·`/filter` 등 HTML stat 영역을 후속 Phase에서 캡처한다.

### 3.2 직렬화 형식

| 요소 | 규칙 |
|------|------|
| 시나리오 구분 | `=== GM-D-XX ===` 헤더 |
| 감정 map | `sentiment\|{키}\|{건수}` |
| 키워드 map | `keyword\|{키}\|{건수}` |
| 필터/CSV 결과 | `count\|{N}` + `text\|{본문}` (입력 순서 유지) |
| 줄바꿈 | LF (`\n`) — `.gitattributes` + `normalizeLineEndings()` |

## 4. 시나리오 매핑 (GM-D-01 ~ GM-D-04)

`docs/test_plan.md` §2·§4, `docs/PRD.md` §3.2 대표 샘플과 정합.

| ID | Given | When | 캡처 대상 | Then (기준 스냅샷) |
|----|-------|------|-----------|-------------------|
| **GM-D-01** | `"배송이 너무 늦어요. 화가 납니다."` | `TextAnalyzer::sent` + `kw` | 감정 map, 키워드 map | 부정=1, 배송=1, 나머지 0 |
| **GM-D-02** | `"그냥 그래요. 특별한 감정 없음."` | `Filters::fil(중립, 전체)` | 필터 text 목록 + 건수 | count=1, 중립 1건 |
| **GM-D-03** | CSV `text\n택배가 빨라요.\n` | `CsvParser::parse` | Feedback text 목록 | count=1 |
| **GM-D-04** | Feedback 3건 혼합 | `Filters::fil(전체, 전체)` | 반환 건수 + text 목록 | count=3 |

**GM-D-04 입력 (FiltersTest T-04와 동일):**

1. `"좋아요 만족합니다."` (긍정)
2. `"배송이 너무 늦어요."` (부정)
3. `"그냥 그래요. 특별한 감정 없음."` (중립)

## 6. 테스트 실행

### 6.1 Approval (회귀 검증)

```powershell
cmake --build build_cov --target feedback_analyzer_tests
ctest --test-dir build_cov -R DomainGoldenMasterTest --output-on-failure
```

| 테스트 | 역할 | 결과 |
|--------|------|------|
| `DomainGoldenMasterTest.Given_DomainScenarios_When_Capture_Then_MatchesGoldenFile` | actual vs expected 바이트 비교 | ✅ Pass |

### 6.2 Capture (기준 파일 갱신 — 의도적 1회)

```powershell
$env:UPDATE_GOLDEN = "1"
ctest --test-dir build_cov -R GoldenMasterCapture --output-on-failure
```

| 테스트 | 역할 | 기본 동작 |
|--------|------|-----------|
| `DomainGoldenMasterCapture.GoldenMasterCapture` | `domain_golden_expected.txt` 덮어쓰기 | `UPDATE_GOLDEN≠1` → **Skip** |

> 프로덕션 로직 변경 후 Golden을 **의도적으로** 갱신할 때만 사용한다. 일반 CI/회귀에서는 Approval 테스트만 실행.
